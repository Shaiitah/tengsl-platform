Режим работы

Переключение выполняется самим Backend через общий runtime-файл. Docker socket и управление Docker daemon из контейнеров не используются.
Текущий режим: —
Development включает hot reload; Production запускает сервисы без hot reload.

Разработка без rebuild

Исходники монтируются в контейнеры в development-режиме
Запуск
docker compose up -d
Тесты
docker compose run --rm backend pytest -q
Миграции БД
docker compose run --rm backend alembic upgrade head
Остановка
docker compose down
Оба режима используют один docker-compose.yml. Runtime-режим хранится в runtime/mode; для переключения из Dashboard пересборка не нужна. PostgreSQL хранит данные в data/postgres.

Что требует пересборки

  • Изменение Dockerfile или системных пакетов.
  • Изменение Python-зависимостей в requirements.txt.
  • Изменение базового образа или production-конфигурации, запекаемой в image.
  • Обычные изменения Python/JS/CSS при смонтированных исходниках пересборки не требуют.
