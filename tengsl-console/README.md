# TENGSL Console

Статический дашборд (без сборки, чистый HTML/CSS/JS) для наблюдения за
зонами и событиями в реальном времени. Подключается к backend'у по REST
(первичная загрузка) и WebSocket (`/ws/events`, живые обновления).

## Запуск как части общего стека

Уже подключён в `tengsl-platform/docker-compose.yml` (см. корневой README) —
просто `docker compose up --build` и открой http://localhost:8080.

## Запуск отдельно, без Docker

Это обычные статические файлы — подойдёт любой веб-сервер, либо для
быстрой проверки:

```bash
cd tengsl-console
python -m http.server 8080
```

Открой http://localhost:8080 — по умолчанию дашборд ожидает backend на
`http://<тот же хост>:8000` (см. `config.js`). Если backend работает по
другому адресу — поменяй `apiBase`/`wsBase` в `config.js`.

## Как это работает

1. При загрузке страницы — `GET /api/objects`, дальше для каждого объекта
   `GET /api/objects/{id}/status`, чтобы раскрасить точки online/offline в
   списке слева.
2. При выборе объекта — `GET /api/objects/{id}/zones` и
   `GET /api/objects/{id}/events?limit=50` для начального состояния.
3. Дальше открывается WebSocket на `/ws/events?object_id=...` — новые
   события обновляют карточку зоны и добавляются в журнал без перезагрузки
   страницы.
4. Список объектов обновляется раз в 30 секунд (на случай, если добавился
   новый объект) — реалтайм-канал при этом не прерывается.

## Известные упрощения (нормально для пилота, не для прода)

- Нет аутентификации — совпадает с текущим состоянием backend'а.
- Список объектов, статусы и зоны хранятся в памяти вкладки браузера — при
  перезагрузке страницы всё подтягивается заново с backend'а, что для
  1-5 объектов быстро и не проблема.
- Журнал ограничен последними 100 событиями на экране (полная история
  всегда доступна через `GET /api/objects/{id}/events` с нужным `limit`).
